# Local development

Runs the site on `http://localhost:3000` with hot reload, a working admin,
LFF sync and a local mail sink. Nothing is sent to production: the database is
a local file, emails are printed in the terminal, and the shared calendar feed
stays disabled. Application code is unchanged; all wiring lives in
`scripts/local/` and the `local:*` npm scripts.

## First run

```bash
NODE_AUTH_TOKEN=$(gh auth token) npm ci
npm run local:setup
npm run local:dev
```

- `npm ci` needs a GitHub token with `read:packages` for `@olaine/database`.
  The token is only used for the install and is never written to a file.
- `local:setup` creates `.env.local` from `scripts/local/env.local.example` if
  it is missing, creates the schema in `./local.db`, runs the shared migrations
  and seeds placeholder data. It is safe to rerun: the seed only fills an empty
  database, so your local edits are kept.
- `local:dev` starts `next dev` (Turbopack, hot reload) and the mail sink.

Admin: `http://localhost:3000/admin`, password `ADMIN_PASSWORD` from `.env.local`.

## Data

- Database: `./local.db`. Uploaded photos: `./uploads/`. Both are ignored by
  git and survive restarts.
- `local:setup` runs the minimal seed from `scripts/local/seed.mjs`: the main
  team "2. liga", the LFF source for the men's 2nd league and fake club
  contacts (`info@afaolaine.test`, a reserved domain). Without contacts the
  public pages fail, so this is the smallest set that lets the site run.
- A fuller private dataset is optional. If `.local/seed.mjs` exists, `local:setup`
  runs it instead of the minimal seed. `/.local/` is git-ignored, so private
  data never reaches the repository.
- To start over, stop the server, delete `local.db`, `uploads/` and `.next/`,
  and run `npm run local:setup` again. Deleting `.next/` clears Next's public
  data cache, which otherwise shows the old data until its next refresh.

## Snapshots

A snapshot is a named copy of `local.db` and `uploads/`, stored in
`.local/snapshots/<name>/` (git-ignored), so a prepared state can be restored
at any time.

```bash
npm run local:snapshot -- save full-demo
npm run local:snapshot -- list
npm run local:snapshot -- restore full-demo
```

- `save` works while the dev server runs and refuses to overwrite an existing
  name (delete the snapshot folder first).
- `restore` replaces `local.db` and `uploads/`, clears `.next/` and refuses to
  run while the dev server is up; stop it first.
- Names may use letters, digits, `-` and `_`. Snapshots hold only the fake
  data you put in the local database; keep real data out of it.
- A snapshot (or `local.db`) saved before a `@olaine/database` upgrade has the old
  schema. After restoring it, run the shared migrations before starting the app
  (do not run `drizzle-kit push` first: it would drop columns the migration still
  needs to copy):

  ```bash
  node scripts/local/run.mjs node node_modules/@olaine/database/migrate.mjs
  ```

## LFF sync

- From the admin: **Līgu avoti** → "Ielādēt spēles" / "Sinhronizēt vārtu guvējus".
- As the production cron does, while `local:dev` is running:

  ```bash
  npm run local:sync
  ```

The sync only reads `https://lff.lv` pages.

## Email

`SMTP_*` in `.env.local` point to `127.0.0.1:2525`, where `local:dev` runs a
small SMTP server (`scripts/local/mail-sink.mjs`). It accepts every message and
prints sender, recipient, subject and text in the `local:dev` terminal; nothing
is delivered. The sync sends an email only when an already imported game's time
or venue differs on LFF.

## Isolation guard

Every `local:*` command goes through `scripts/local/run.mjs`. It loads only
`.env.local` (its values override shell variables) and refuses to run when:

- `.env`, `.env.development*` or `.env.production*` exists in the project root;
- `NODE_ENV` is `production`;
- `TURSO_DATABASE_URL` is not a `file:` URL, or `TURSO_AUTH_TOKEN` is set;
- `SMTP_HOST` is set to anything other than a loopback address;
- `SHARED_CALENDAR_SECRET` is set;
- `SITE_URL` does not point to localhost.

## Notes

- `next dev` in Next.js 16.3 creates `AGENTS.md` and `CLAUDE.md` in the project
  root. They are generated by Next itself, not by these scripts.
- `npm run build` fails with `Cannot read properties of null (reading
  'useContext')` when the shell exports `NODE_ENV=development`. Build with
  `NODE_ENV=production npm run build -- --webpack`, as the server does.
